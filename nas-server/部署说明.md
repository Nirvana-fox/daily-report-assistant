# NAS 服务端部署说明

本目录是「日报助手」的 **NAS 服务端**：接收局域网内电脑客户端推送的工作记录和截图原图（图片单独按日期存放），并提供与小黑日报助手兼容的查询 API。

```
nas-server/
├── app.py               # Flask 服务（单文件，无其他本地依赖）
├── requirements.txt     # flask + gunicorn
├── Dockerfile
├── docker-compose.yml
└── 部署说明.md
```

## 数据存储结构

```
/data
├── nas.db                # SQLite：工作记录 + 应用时长会话
└── images/               # ★ 截图原图单独保存（不进数据库）
    └── 2026-09-06/
        └── 06/
            └── DESKTOP-ABC/
                └── log123_shot_20260906_120000.png
```

- 图片按 `日期/日/设备ID/` 分目录，文件名带来源记录 id，方便回溯。
- 同一记录的图片重复上传会自动去重（不重复占空间）。

## 方式一：Docker 部署（推荐，群晖/威联通/TrueNAS 均适用）

1. 把整个 `nas-server/` 目录上传到 NAS（如 `/volume1/docker/report-assistant-server/`）。
2. SSH 进入 NAS（或用 Container Manager 图形界面）：

```bash
cd /volume1/docker/report-assistant-server
# 修改 docker-compose.yml 里的卷路径和 TOKEN
docker compose up -d --build
```

3. 验证：浏览器打开 `http://<NAS_IP>:8088/api/health`，应返回 `{"code":0,...}`。

> 群晖 Container Manager：项目 → 新建 → 选择该目录 → 构建；端口和目录在 yml 里改。

## 方式二：直接跑 Python

适合 NAS 上有 Python 3.10+ 或临时测试：

```bash
pip install -r requirements.txt
TOKEN=你的令牌 PORT=8088 python app.py
# 或 Windows: set TOKEN=xxx && python app.py
```

## 客户端配置（电脑上的日报助手）

打开 日报助手 → **设置 → NAS 同步**：

| 配置项 | 值 |
|--------|-----|
| 启用 NAS 同步 | ✔ |
| 服务端地址 | `http://<NAS_IP>:8088` |
| 访问令牌 | 与服务端 `TOKEN` 一致（服务端未设则留空） |
| 设备 ID | 留空自动取主机名（多台电脑建议手动命名） |
| 同步截图原图 | ✔（未勾选"分析后保留图片"时，推送成功后自动删除本地截图） |

点 **保存并测试连接** → 显示"连接成功"即完成。之后每 30 秒自动增量同步，也可点 **保存并立即同步**。

## 同步机制

- **增量推送**：客户端按本地记录 id 游标逐条推送，断网/关机后下次自动补推。
- **首次启用**只同步"从现在开始"的新记录，不上传历史。
- **幂等去重**：NAS 端按 `(设备ID, 记录ID)` 去重，客户端重试不会造成重复。
- **图片**：客户端先传图、再传记录；`keep_after_analysis=false` 时图片推完即删本地（本地不留隐私文件，NAS 上留档）。

## 与其他设备联动

- 数据聚合在 NAS 上后，任何设备都能通过查询 API 读取：
  - `GET /api/timeline?startDate=2026-09-01&endDate=2026-09-06`
  - `GET /api/app-usage?...` / `GET /api/heat-map?...` / `GET /api/records?...`
- 返回格式与小黑日报助手一致，原小黑生态的脚本/页面可直接切换到本服务。

## 安全建议

1. **一定设置 TOKEN**（compose 里改 `TOKEN` 环境变量），防止局域网内他人写入。
2. 服务端只监听局域网；不要把 8088 端口映射到公网。
3. 截图属于敏感数据，NAS 共享目录建议开启 DSM 权限控制。
